# Native portable package

The native package is a Windows x64 distribution of the process-worker path.
It contains no Python interpreter, PyTorch, model weights, or user recordings.
Models are provisioned separately under `models/` and are deliberately marked
as mutable in the release manifest.

## Contents

```text
bin/qwen_tts_native_worker.exe
bin/qwen_tts_save_wav.exe
bin/qwen_tts_play.exe
runtime/qwentts/qwen.dll
runtime/qwentts/<GGML and CUDA DLL closure>
runtime/qwentts/manifest.json
config/native-dependency-policy.json
config/native-package.example.json
dependency-inventory.json
release-manifest.json
SHA256SUMS.txt
```

The runtime manifest is generated by
`scripts/write-qwentts-runtime-manifest.py` from the prepared qwentts.cpp
runtime. The package assembly step verifies every listed hash and rejects
unmanifested files, model formats, and fake/test runtime names. The dependency
inventory is produced by the standard-library PE import auditor and separates
bundled DLLs from guaranteed Windows files and explicitly declared deployment
prerequisites. Missing CUDA/VC++ files, delay-load imports, and declared
dynamic backend modules fail the audit unless the policy names them explicitly.
The policy is evidence about deployment requirements, not proof that a clean
machine can load the package.

## Build and assemble

Build the worker and the two Windows utilities with the same x64 Release
configuration. Prepare a real qwentts.cpp runtime directory containing
`qwen.dll`, its complete GGML/CUDA DLL closure, and its manifest. Then run:

```powershell
pwsh -File scripts/assemble-native-portable-release.ps1 `
  -NativeWorkerExecutable build/native/Release/qwen_tts_native_worker.exe `
  -RuntimeRoot E:/models/qwentts-runtime `
  -SaveWavExecutable build/default/Release/qwen_tts_save_wav.exe `
  -PlayExecutable build/default/Release/qwen_tts_play.exe `
  -NoticeFile LICENSE,external/cpp/qwentts.cpp/LICENSE,external/cpp/qwentts.cpp/ggml/LICENSE `
  -EngineCommit 130cb99af9ae12d554962fd0920e08fb4268af01 `
  -OutputRoot dist/QwenTTSBridge-native `
  -ZipPath dist/QwenTTSBridge-native.zip `
  -Clean
```

The release-specific configuration is `config/native-package.example.json`.
Its `runtime_dir` is `runtime/qwentts` and its model paths are relative to the
package root, so it remains valid after relocation. It intentionally contains
no CMP-specific runtime name or checkout path.

The command fails closed when the runtime manifest is missing, a hash differs,
an import/export cannot be resolved, a path overlaps an input, a reparse point
is encountered, or a model/test artifact is present. It does not download
models or runtime DLLs. The staging directory is verified before publication;
the ZIP is created and reopened with `scripts/verify-native-package.py`, which
checks hidden files, manifest entries, checksums and extraction. A successful
assembly is a package artifact, not yet a hardware or listening acceptance
result.

The package must include redistributable notices for the Bridge, qwentts.cpp,
GGML and any bundled CUDA/VC++ components. Pass those files explicitly through
`-NoticeFile`; the default Bridge `LICENSE` is not a complete third-party
notice inventory for a release.

## Relocation gate

Extract the ZIP outside the source checkout, provision models explicitly, and
run the native worker with `--runtime-dir runtime/qwentts`. Verify the ready
handshake, non-empty PCM, natural EOS, repeated requests, cancellation and
restart before making a support claim. Run the same sealed package on CMP 50HX
and RTX 4090 and retain the package manifest, runtime manifest, dependency
inventory, checksums and hardware receipts together.

The Python/FasterQwen distribution remains a separate supported backend. The
native package must never embed the existing Python portable runtime.
